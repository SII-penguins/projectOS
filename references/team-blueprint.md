# Team Workflow

Use when the project needs a durable collaboration contract. Existing user authorization, host capabilities, budgets, and project boundaries determine whether delegation is available. Creating `TEAM.md` does not start a team.

`TEAM.md` owns stable collaboration rules. Current assignments belong to the active queue, current blockers to live state, and run outcomes to the ledger.

## Choose useful boundaries

Delegate independent bounded work when authorized and likely to save time or improve quality. Keep a tightly coupled diagnosis with one owner. Define editable files or modules and expected output before parallel writes; do not give two workers the same evolving edit surface.

Use concurrency appropriate to available independent work and resource limits. There is no mandatory worker count, resident role roster, or burst tier. One agent is sufficient when coordination would cost more than it contributes.

The coordinating agent integrates results and communicates project decisions. It may implement a disjoint part or continue alone when that best serves the task. A reviewer assigned read-only review remains read-only unless reassigned; independent review is required only where the task or project acceptance requires it.

## Assignment and handoff

An assignment should state the result needed, relevant context, edit boundary, permitted resources, acceptance, and genuine stop conditions. Existing scope and execution authorization carries forward; tool approval does not create new project scope.

A handoff gives changed files, observed behavior, verification evidence, relevant untested limits, and facts that need promotion into canonical documents. Use only fields that help the receiving agent act. Messages and scratch notes are transient coordination, not alternate project state.

For an independent behavioral evaluation, give the evaluator the realistic request and necessary raw artifacts without the expected answer or proposed fix. Evaluate its actual actions and output against the acceptance criteria separately.

## Continuity and decisions

On resume, verify ownership and active work relevant to the next task. Repair stale assignments without disrupting still-running workers. A missing worker or old pane should not require rebuilding the whole team if a local reassignment is sufficient.

Workers may align technical details within their assignments. Material scope, resource, contract, or acceptance changes return to the coordinating agent and, where existing authorization is insufficient, to the user. Stop only dependent work while the decision is pending.

Before integration, check the evidence needed for the actual claim and reconcile changed owners. Avoid repeating a test merely because another role took over; repeat when the integrated change or an unresolved issue warrants it.
