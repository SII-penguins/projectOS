# Planning Question Bank

Use only when a decision needed for the current work remains unresolved after inspecting available evidence. These prompts are coverage aids, not required user questions. Use the smallest relevant section, resolve routine choices from context, and defer later-stage unknowns.

## Outcome and acceptance

- What result does the user need now: a plan, implementation, reconciliation, or closeout?
- What is in scope and out of scope, and what would establish success?
- Does the user want a staged review, or is the requested work already authorized?
- What consequential choice cannot be inferred from the supplied material?

## Existing state

- Which facts conflict, and what current evidence can resolve them?
- Where are live state, tasks, roadmap and run history already owned?
- What is the valid next action, and which real dependencies or restrictions affect it?
- What work is terminal, what remains blocked, and what would unblock it?

## Evidence and research

- What is the research question, claim boundary and potential falsifying evidence?
- What inputs, outputs, data provenance, splits and leakage controls apply?
- Which named baselines, configurations, metrics and aggregation make comparison meaningful?
- Which resource budget and run mode is already authorized?
- What artifact proves the asserted outcome, and what remains smoke-only or unverified?

Ask about details such as optimizer, seed, retry limits or retention when the current experiment depends on them, not before a high-level project plan can exist.

## Lifecycle and collaboration

- Which facts must survive reconciliation and where will their evidence remain?
- Are active references, acceptance or review still unresolved for a proposed archive item?
- What deletion scope and recovery path are established?
- If collaboration is requested or already active, what ownership boundaries, resources and handoffs matter?

Let the agent choose filenames and a small document map when those are routine implementation choices. Preserve project-specific constraints and user preferences instead of asking the user to learn internal document roles.
